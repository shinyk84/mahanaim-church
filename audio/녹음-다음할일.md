# 듣기 녹음: 다음에 할 일 (2026-11-14 기록)

## 지금 상태
- 구원의 길 한국어: Gemini로 원고 전체를 한 번에 녹음해서 반영함(`audio/gospel/ko.mp3`). 사용자 확인 완료("아주 좋아").
- 777 기도 한국어: 녹음 대신 RUTCTV 공식 유튜브 영상(9LS5xRoEu3M)을 작은 창으로 재생함(`content/audio.json`의 `youtube` 항목).
- 나머지 9개 언어(en, ur, zh, ja, fr, de, es, ru, km)는 구원의 길과 777 기도 모두 아직 예전 Azure 녹음임.

## 다음에 할 일: 9개 언어 × 2(구원의 길, 777 기도) 녹음
사용자는 다른 언어를 들어도 판단하기 어렵다고 함. 그래서 한국어에서 확인받은 방식을 그대로 쓰고, 품질은 자동 점검에 맡김.

```
python scripts/tts_gemini.py gospel en --whole
python scripts/tts_gemini.py prayer777 en --whole
```
- `--whole`: 원고를 나누지 않고 한 번에 녹음함. 조각 이음새에서 목소리가 바뀌는 문제를 피하려는 것으로, 한국어에서 확인받은 방식임.
- `--draft` 없이 실행하면 `audio/<page>/<lang>.mp3`에 바로 저장되고 사이트에 반영됨.
- 777 기도: 제목, 소제목, 항목 이름은 읽지 않고 기도 문구만 읽음. 문구 끝에 마침표를 붙이고, 항목 사이는 0.45초, 줄 사이는 0.12초를 더 쉼(`widen`).
- 자동 점검: 받아쓰기로 원고와 맞는 정도(95% 이상), 녹음 안에서 목소리 높낮이가 바뀌는지(4% 이하)를 봄. 통과하지 못하면 최대 3번까지 만들고 가장 나은 것을 고름.
  - 한국어 777은 6번 모두 높낮이 기준을 통과하지 못했음(측정이 2% 단위로 거칠어서임). 그러니 3번 만들어 가장 나은 것을 쓰고, 결과를 사용자에게 보고하면 됨.
- 777 기도는 숫자와 약어(237, 5력, CVDIP, 7망대 등)를 읽는 법이 언어마다 다름. 녹음하기 전에 `content/prayer777/<lang>.json`의 숫자 표기를 확인하고, 필요하면 `SAY`에 그 언어 항목을 추가할 것. 지금은 한국어만 있음.

## 하루 무료 한도 (한국시간 오후 5시에 다시 채워짐)
- `gemini-3.8-flash-tts`(기본) 하루 10번, `gemini-3.8-flash-lite-tts` 하루 10번. 두 모델은 따로 셈함.

- 언어 하나에 1~3번이 쓰임. 18개 녹음이면 이틀 정도 걸릴 수 있음.
- 받은 소리는 `.transcript-work/tts/`에 바로 저장되므로, 중간에 멈춰도 다시 실행하면 이어서 함.
